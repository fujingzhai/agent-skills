# B站视频文稿整理

从一条 B站视频链接产出可靠、可读、可追溯的文稿，落成普通 DOCX 文件。

## 硬边界

- 用户只说“总结”“摘要”“概括”时，仍按全文文稿流程做：开头写实质摘要，正文保留完整逐字稿；**严禁只输出一篇总结稿**。只有用户明确限定“只要摘要、不要全文”时才可以只写摘要。
- 开工先跑 `yt check` 检查依赖；缺少 yt-dlp（可执行文件与 Python 库）时按输出安装。
- 先探测高质量现成文稿，再决定是否整理字幕。
- 只把人工 CC 或平台 AI 字幕当语音字幕；`danmaku` 是弹幕，永远排除。
- 没有可靠现成文稿且没有可用字幕时立即报告并停止。不要下载音频，不要调用本地或云端 ASR。
- Cookie 只从本机浏览器登录态读入内存；不得打印、导出或保存 Cookie 值。
- 现成文稿的来源与完整性必须核验，不能把第三方 ASR 聚合站当成优质底本。

## 全流程

```text
⓿ yt check            检查依赖（yt-dlp 可执行文件与 Python 库）
① bili doc <url>      登录探测 → 选最佳字幕 → 下载 → 清洗
② 查现成文稿          依据候选链接和检索式，最多检索 3 次
③ 选择底本            优质现成稿优先；否则使用人工 CC / 原生 AI 字幕
④ 整理成稿            校错、分节、高亮；字幕底本另写实质摘要
⑤ 导出 DOCX           用 scripts/to_docx.py 生成单个 docx 并读回验证
⑥ 清理工作区          用根命令 `yt rm`，移入废纸篓
```

① 是机械步骤；②—④需要判断。即使 `bili doc` 已经下载字幕，仍要完成②，不能因为"有字幕"就跳过优质文稿。

> 本文件中的 `yt` / `bili` 指套件内脚本。若你不在套件目录内：
> `python3 <套件目录>/yt ...`、`python3 <套件目录>/skills/bilibili-transcript/bili ...`；
> `<套件目录>` 从本文件所在位置向上两级。

## ⓿ 依赖检查

```bash
yt check
```

B站子技能额外需要 `yt_dlp` Python 库（脚本要 `import yt_dlp`）。检查输出里
`yt_dlp库` 一项必须是「已安装」，否则按它给的命令安装：`python3 -m pip install -U yt-dlp`。

## ① 探测和取字幕

```bash
# 完整机械流程：探测、下载最佳字幕、生成 transcript.txt
python3 <套件目录>/skills/bilibili-transcript/bili doc "<B站URL>"

# 也可从套件统一入口调用
yt bili doc "<B站URL>"

# 只探测，不下载字幕
yt bili probe "<B站URL>"

# 只下载字幕，不生成 transcript.txt
yt bili subs "<B站URL>"
```

脚本默认使用 Arc `Default` profile；设置 `BILI_BROWSER=chrome` 可改用 Chrome。Arc 的 `SESSDATA` 通过 macOS 钥匙串 `Arc Safe Storage` 解密，全程只驻留内存；**非 macOS 上 Arc 不可用，必须 `BILI_BROWSER=chrome`**。

选轨顺序：

1. 人工 CC 中文字幕
2. 其它人工 CC 字幕
3. 平台 AI 原生中文字幕（通常为 `ai-zh`）
4. 平台 AI 原生其它语言字幕

`ai_type=1` 的 AI 翻译轨不自动采用，避免在识别误差上再叠机器翻译误差。非中文原生字幕由 agent 通读后翻译。

成功后工作区包含：

- `meta.json`：视频、分P、字幕轨、文稿候选、检索式与底本风险
- `*.srt`：B站原始时间轴转换出的 SRT
- `subtitle.json`：B站字幕 JSON 原始响应
- `transcript.txt`：按段落合并、保留 `[HH:MM:SS]` 的底稿

如果只有弹幕、字幕元数据无 URL，或根本没有字幕轨，命令返回非零状态并明确打印"没有可用字幕"；仍会保留 `meta.json` 中的现成文稿检索式。此时只允许完成②；找不到可靠现成稿就停。

字幕元数据必须通过 yt-dlp 当前的 WBI 签名接口取得；不要改成匿名 `/x/player/v2`。后者实测可能返回其它视频的陈旧字幕 URL，造成"标题正确、正文串片"的静默错稿。

## ② 查高质量现成文稿

先读 `meta.json`：

- `transcript_candidates`：描述栏直接给出的候选链接，必须逐一检查。
- `search_queries`：脚本按标题、UP主、节目名生成的检索式。
- `search_recommended` / `search_reason`：是否值得主动检索及原因。

以下场景必须搜索：

- 描述栏出现"全文、文字版、实录、逐字稿、公众号、show notes"等线索；
- 访谈、播客、对话、演讲、圆桌、讲座、口述史；
- 字幕为平台 AI 且视频超过 20 分钟；
- 多人对话，字幕没有说话人标注。

按 `search_queries` 最多检索 3 次，命中可信来源后停止。优先顺序：节目/UP主官网或公众号 → 联合出品方、嘉宾机构 → 明确授权转载的媒体全文。还可检查同一节目在 YouTube、播客 RSS、小宇宙等平台的描述栏；B站描述可能省略外链。

来源分档、核验方法和"张小珺商业访谈录"范例见 [source-quality.md](references/source-quality.md)。使用现成稿之前必须完整阅读该文件。

## ③ 选择底本

```text
第一方/授权的完整逐字稿    → 取代字幕；保留原文结构与说话人，不再 AI 重写
第一方高质量编辑稿         → 若它就是节目正式文字版，直接作为"官方编辑稿"入库
第三方全文转载             → 只有能确认来源、版本和完整性时才采用
第三方 ASR/摘要/付费墙残文 → 不采用；回到B站字幕
```

如果采用优质现成稿：

- 保留原有标题、分节、说话人和正文，不另写一篇 AI 摘要替代它。
- 文首增加来源块：节目、嘉宾、发布日期、原视频、现成稿链接、底本档次、是否完整逐字或编辑稿。
- 对完整稿抽查开头、中段、结尾；与视频版本不一致时，退回字幕底本或明确标出删节。

如果采用字幕：

- 人工 CC 只需通读校错；平台 AI 字幕必须重点核对人名、机构、产品、书名、数字和说话人。
- 确定的识别错误直接改；不确定处标红并加 `<sup>（说明）</sup>`，禁止猜测。
- 不删除整句，不把逐字文稿压缩成"内容摘要"。

## ④ 整理字幕底本

现成优质稿按③直接入库；只有字幕底本才执行本节。

### 文首元信息

用引述块列出节目/UP主、嘉宾、主持人、发布日期、时长、原片链接、底本说明。底本说明必须写明"人工 CC"或"B站平台 AI 字幕"、语言轨、是否参考现成稿。

### 全文摘要

在正文前写 `## 全文摘要`，约 500 字。必须包含具体主张、数字、人名、结论和转折；不要写"围绕某话题进行了深入讨论"之类元描述。

### 正文

- 按话题切 `##` 小节；一小时访谈通常 15—30 节。
- 保留 `[HH:MM:SS]` 时间戳。
- 每节用 `==高亮==` 标 1—2 个关键观点；不高亮单纯术语或人名。
- 中文字幕不翻译。非中文字幕以中文在前、原文引述块在后，原文不得压缩或改写。
- 存疑处写法：`存疑内容<sup>（说明）</sup>`（转成 Word 上标小字）与
  `<span style="color: #d23f31;">存疑内容</span>`（转成 Word 红色字）。

## ⑤ 导出 DOCX

用套件自带的纯标准库脚本把成稿 markdown 转成单个 DOCX（不依赖 pandoc / python-docx）：

```bash
python3 <套件目录>/scripts/to_docx.py -o "<输出目录>/<标题>.docx" part1.md [part2.md ...]
```

- **输出目录**：默认 `YT_OUTPUT_DIR`；未设置时放在当前工作目录下 `yt-transcript-output/`。
  文件名用视频/节目标题，去掉 `/\:*?"<>|` 等非法字符。
- 长文分批写 md，最后所有 part 按顺序传给 to_docx.py 一次合并。
- 生成后**必须**读回验证（解包 docx 抽查，或 macOS `textutil -convert txt` / Word 打开），
  确认标题、摘要、分节、时间戳、来源链接及末段都在。

## ⑥ 清理

确认 DOCX 完整后：

```bash
yt rm <BV号或视频URL>
```

该命令把任务工作区移入废纸篓，可恢复；不得用 `rm -rf`。

## 交付检查

- [ ] 已跑 `yt check`，yt-dlp 可执行文件与 Python 库就绪
- [ ] 用户说“总结/摘要”时，交付的仍是全文文稿 + 开头摘要，不是只有一篇总结稿
- [ ] 使用有效登录态探测，未把弹幕当字幕
- [ ] 描述栏候选已检查；应搜索的访谈/播客已完成最多 3 次检索
- [ ] 现成稿已核验来源、版本、完整性并标明档次
- [ ] 无现成稿且无字幕时已停止，没有下载音频或调用 ASR
- [ ] 字幕底本有实质摘要、分节、时间戳、高亮和专名校对
- [ ] 已导出单个 DOCX 并读回验证，文首写明底本与来源
- [ ] Cookie 从未落盘或输出
- [ ] 临时工作区已移入废纸篓

## 排错

| 症状 | 处理 |
|---|---|
| `yt check` 报 `yt_dlp库` 未安装 | `python3 -m pip install -U yt-dlp` |
| `Arc 中没有有效的 B站登录 Cookie` | 在 Arc 登录B站后重试；或设置 `BILI_BROWSER=chrome` |
| 非 macOS 上 Arc 报错 | Arc 的 Cookie 读取依赖 macOS 钥匙串；设 `BILI_BROWSER=chrome` 并在 Chrome 登录B站 |
| `find-generic-password failed` | 解锁登录钥匙串，并确认存在 `Arc Safe Storage` |
| 只看到弹幕 | 登录态无效或视频确实无字幕；以 `meta.json` 的 `subtitle_tracks` 和错误类型为准 |
| 字幕有语言名但 URL 为空 | 视为不可用字幕，不能假装成功 |
| HTTP 412/风控 | 停止并稍后重试，不循环轰炸接口 |
| 分P取错 | 在 URL 保留 `?p=N`，工作区会写成 `<BV号>_pN` |
